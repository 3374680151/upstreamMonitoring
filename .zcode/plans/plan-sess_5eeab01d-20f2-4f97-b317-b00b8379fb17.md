## 需求（已对齐）

一个**系统级开关「同步全部渠道」**（默认开）：

- **开**：主站同步导入全部渠道（= 现状行为，完全不变）
- **关**：只把 base_url 被识别为 **NewAPI / sub2api** 的渠道导入为监控站点，未识别平台（如指向 OpenAI 官方的渠道）跳过不导入
- 已导入的未识别站点**保持原样**（不停用、不删除）——「不同步」≠「删除」，符合兼容性红线
- 渠道列表页是实时镜像主站（页面本就标注"实时读取 NewAPI /api/channel"），不属于同步产物，开关不影响它；开关影响的是「同步 → 导入监控站点」这一步
- 说明：候选导入只发生在 NewAPI 主站分支（sub2api 主站同步本来只落快照不导入），开关对 sub2api 主站无实际影响

   - 新增公开方法 `platforms_for_base_urls(base_urls) -> Dict[str, str]`：供同步过滤复用同一套识别逻辑与缓存

4. **`backend/services/sync_service.py`**
   - `_run_admin_site_sync` 读开关，`_sync_one_admin_site(admin, mode, sync_all)` → `_sync_admin_site_snapshot_in_connection(..., sync_all)`
   - newapi 分支中 `sync_all=False` 时：`aggregate_newapi_channel_candidates` 的结果按 base_url 平台分成「识别组(newapi/sub2api) / 未识别组(unknown)」：
     - 只对识别组执行 `_import_discovered_site_item`
     - **对账 `_reconcile_site_discovery_links_in_connection` 传入识别组 + 未识别组全量**（关键：未识别渠道不能被当成"上游已消失"而误删链接/停用站点）
     - entry 返回增加 `sync_all`、`excluded_candidates`、`excluded_channels`（跳过的渠道数）
   - `live_channel_ids` 仍用全量 channels，绑定/key 清理逻辑不变

5. **`backend/api/routers/monitoring.py`** `/sites/sync`
   - 响应增加 `sync_all`（`get_main_site_sync_all_channels()`）与 `excluded`（各 entry `excluded_channels` 求和）
