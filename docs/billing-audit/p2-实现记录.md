## 1. 本次范围（方案 §12 P2 剩余项）

| 项 | 结论 / 落点 |
|----|------|
| sub2api 上游日志核对 | 上游 `GET /api/v1/usage`（page 从 1 起、limit≤500、时间倒序），实扣即美元 `actual_cost`，无 quota 换算 |
| `push_on_red` 告警 | 每轮核对新增红色行 → 按推送配置发邮件/企微；单轮一封汇总，最多列 8 条明细 |
| `quota_per_unit` 按站点覆盖 | `sites` / `admin_sites` 各加 `INT NULL` 列；上游用站点级、主站收入用主站级，NULL 回落全局 |
| 官方价定时同步 | 每天回放 sub2api 主站快照里的 `model_pricing` → `official_model_prices`，`source='sub2api'`，**不覆盖 `manual` 行** |
| 灰行自动重判 | 上一轮遗留项：`no_binding / no_token / no_log_api` 的灰行每轮重试，成因修复后自动转绿/红 |

## 2. 新增文件（一文件一功能）

| 文件 | 职责 |
|------|------|
| `integrations/sub2api_logs.py` | usage 拉取 + `normalizeSub2apiUsageLog`（对齐 NewAPI 消费日志键位）+ `sanitizeSub2apiUsageRaw`（剥 `api_key.key` 与用户邮箱后才能进证据快照列） |
| `services/billing_audit_rules.py` | EPS / `safeNumber` / `relDiff` / `officialCost` 纯规则，NewAPI 与 sub2api 判定共用 |
| `services/billing_audit_sub2api.py` | `judgeSub2apiUpstream`：自记 `rate_multiplier` vs 监控快照公示倍率（金额兜底），不一致 → 红 `upstream_ratio_drift` |
| `services/billing_audit_notify.py` | `formatRedAlertMessage` + `maybePushRedAlert`：红行汇总推送（复用既有邮件/企微发送器，自记 `notification_logs`） |
| `services/billing_price_sync_service.py` | `collectSub2apiOfficialPrices`（token 价 ×1e6 → USD/1M，per_request → 按次，image 跳过）+ `syncOfficialPricesFromAdminSites`（只读本地 `admin_site_sync_state.channels_json` 回放，不打上游） |

## 3. 关键改动

- `billing_audit_service.py`：`_ensureUpstreamLogs` 按 sub2api 上游切 usage 分页（上限 `SUB2API_USAGE_MAX_PAGES=6`）；`_auditRow` 分平台分支判定；主站收入基准支持 `admin_site_quota_per_unit` 覆盖；每轮对 `listRejudgeBillingChecks`（1 小时冷却 + 每轮 300 条）重判；`runBillingAuditOnce` 收集本轮红行触发 `maybePushRedAlert`（`mismatch_rows` 仅进程内用，不进 API 契约）
- `repositories/billing_audit.py`：`upsertOfficialModelPriceSynced`——`IF(source='manual', keep, VALUES)` 逐列保护人工价；`listRejudgeBillingChecks` 只捞三类可修复灰因（不含 `matched+no_official_price`，避免重匹配倒退）
- `repositories/sites.py` / `admin_sites.py`：`parse_quota_per_unit_override` 下沉 `core/normalize.py`（第二使用方出现后下沉）；create/update/payload 三处接线
- `workers/scheduler.py`：新增 `billing-official-price-sync` 任务（interval 24h）
- 前端：站点表单（仅 NewAPI 显示）、主站表单「Quota 兑美元基准」输入；BillingSettingsDialog 去掉「即将支持」；BillingPricesDialog 加「sub2api 同步」徽章；类型同步

## 4. 自测结果（真实库）

- 迁移幂等执行，`sites.quota_per_unit` / `admin_sites.quota_per_unit` 列就位；
- 手动 `runBillingAuditOnce`：inserted=25、checked=325、**mismatch=8**（此前 0 红）；
- 红色样例：gemini-2.5-flash 主站收用户 $0.000026（group_ratio=1.0），上游「反重力Gemini」分组实付 $0.00000231（rate 0.1）→ 约 11 倍差价，`main_billing_inconsistent + group_ratio_gap`；
- 证据快照已脱敏（无 `api_key.key`、无用户邮箱）；
- 注意：正式 8000 实例是旧代码，仍会把 sub2api 上游行判成 `no_log_api`；灰行重判会在新进程接管后自动翻案（1 小时冷却）。

## 5. 已知边界

- sub2api usage 只能回看 ~500×6 条（时间倒序），更久远的灰行等新请求落库后靠重判翻案；
- 官方价同步只回放**最近一次主站同步成功**的快照，主站长期没同步则价格也停更（日志会打印 `[官方价同步]`）；
- 告警只在「本轮新增红行」时发，历史红行不重复轰炸；单轮上限 8 条明细。
