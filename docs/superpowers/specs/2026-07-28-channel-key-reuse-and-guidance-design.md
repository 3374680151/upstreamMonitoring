# 渠道 Key 复用与待验证提示设计

## 目标

修复主站渠道已经正常运行、但本地没有保存明文 key 时被误报为“渠道匹配失败”的问题。修改仅发生在 Upstream 项目，不改变 NewAPI 的接口或安全策略。

## 已确认根因

NewAPI 的普通渠道详情接口不会返回明文 key。当前项目虽然有 `admin_channel_keys` 缓存表，但新建或修改渠道时没有把用户刚提交的明文 key 写入缓存；修改 key 后还会清除缓存。匹配流程也没有优先复用 `channel_upstream_bindings.channel_key`。因此没有历史缓存的渠道会直接调用受 2FA proof 保护的 key 接口，并把 `SECURITY_PROOF_REQUIRED` 当作硬失败。

## 设计

1. 渠道创建成功并取得渠道 ID 后，将本次提交的非空、非掩码 key 写入 `admin_channel_keys`。
2. 渠道修改成功后，若请求包含真实 key，则更新缓存；若请求明确提交空值或掩码值，则清除缓存，避免继续使用旧 key。
3. 匹配 key 的顺序固定为：主站持久化缓存、渠道绑定保存的 key、渠道详情中的明文 key（兼容特殊 NewAPI 版本）、受保护的主站 key 接口。
4. 从绑定或详情取得真实 key 时同步写入主站缓存，后续请求直接复用。
5. 当唯一阻塞原因是缺少或失效的安全 proof 时，返回 `needs_key_verification`，并将请求视为可恢复状态而不是渠道故障。提示明确说明渠道运行正常、操作入口和后续复用行为。
6. 其他错误（主站不可达、限流、用户 token 错误、key 不存在）继续按真实失败处理。

## UI 行为

`needs_key_verification` 使用黄色 warning 状态。手动刷新时显示信息提示，不出现红色“上游匹配失败”。提示文案为：

> 渠道运行正常，但本地尚未保存该渠道 key。请点击“编辑主站”，输入当前 2FA 验证码完成一次 key 读取安全验证；也可编辑渠道重新填写 key。保存后将自动复用，不再重复验证。

## 测试边界

- 匹配优先复用绑定 key，不调用受保护接口。
- 缺少 proof 时返回 `needs_key_verification` 和可操作提示。
- 创建渠道后保存本次提交的 key。
- 修改渠道 key 后更新缓存，不再无条件清除。
- 前端把 `needs_key_verification` 显示为 warning。
- 现有后端测试、Web Node 测试和生产构建全部通过。
