# 渠道倍率刷新失败与错误原因展示设计

## 背景与根因

主站渠道按 Base URL 复用本地 `sites` 登录态时，如果没有渠道级 binding，`persist_channel_match()` 会直接返回。最近一次成功倍率因此只存在于当前 React 页面状态，刷新页面后便丢失。

当上游连接被重置、超时或限流时，前端把完整 `match_message` 直接作为倍率 Badge 文本，同时手动刷新又在渠道名称下重复显示相同错误。这会用长错误覆盖倍率列，并且无法回退到最近一次成功结果。

本地渠道详情页则直接输出 Python/urllib 原始错误，用户看得到技术字符串，却看不清实际原因。

## 目标

- 自动复用本地 `sites` 登录态的主站渠道也保存最近一次成功倍率。
- 刷新失败时保留并显示最近一次成功倍率，明确标记数据已过期。
- 倍率列不再显示整段原始异常。
- 主站渠道行与本地渠道详情页都明确显示中文错误原因，同时保留原始错误供排查。
- 不新增渠道级登录配置，不修改真实主站渠道，不改变 `/api/sites` CRUD。

## 后端设计

`persist_channel_match()` 在找不到 `channel_upstream_bindings` 行时，创建仅包含以下字段的占位记录：

- `admin_site_id`
- `channel_id`
- 默认空 `upstream_base_url`
- 创建和更新时间

空 `upstream_base_url` 表示仍然继承同 Base URL 的本地 `sites` 登录态，不是渠道级认证配置。

成功匹配时写入 `match_status`、`match_message`、`matched_groups_json` 和 `matched_at`。失败时，如果已经存在非空 `matched_groups_json`，只更新错误状态和消息，不清空成功结果或 `matched_at`。

现有 `match_channel_upstream_binding()` 判断保持不变：只有 binding 的 `upstream_base_url` 非空时才使用渠道级配置，否则继续调用 `find_monitor_site_for_channel()`。

## 错误解释

新增前端纯函数，把常见原始异常转换为用户可理解的原因：

- `Errno 54`、`Connection reset by peer`、`ECONNRESET`：上游主动重置连接。
- timeout：连接上游超时。
- DNS/name resolution：无法解析上游域名。
- HTTP 401/403：上游拒绝认证或访问。
- HTTP 429：上游触发请求限流。
- 其他错误：上游请求失败。

返回值同时保留原始错误文本。中文原因用于主文案，原始错误放在次级等宽文本或 tooltip 中。

## 主站渠道列表

### 有最近成功倍率

继续显示原分组和倍率，下面增加黄色提示：

`刷新失败，显示上次成功倍率 · 原因：上游主动重置连接`

原始异常放在提示的 `title` 中。不能把成功倍率替换成长错误。

### 没有成功倍率

倍率列显示短 Badge `刷新失败`，下面明确显示：

`错误原因：上游主动重置连接`

手动刷新失败时，渠道名称下只显示一次简短状态；完整原因由倍率列和顶部错误条展示，避免重复长文本。

## 本地渠道详情页

错误横幅分为两行：

1. `错误原因：上游主动重置连接`
2. `原始错误：<urlopen error [Errno 54] Connection reset by peer>`

第一行使用危险色强调，第二行使用较弱的等宽文本。用户能看懂原因，也不会丢失诊断证据。

## 测试

- 后端测试：无 binding 时创建占位记录并保存成功倍率。
- 后端测试：后续刷新失败不清空成功倍率。
- 前端纯函数测试：连接重置、超时、DNS、HTTP 403、HTTP 429 和未知错误。
- 前端源码契约测试：倍率列使用短状态与错误原因，不直接把 `match_message` 作为 Badge 文本。
- 页面构建、全部 Python 测试和全部 Web 测试通过。
- 浏览器验证主站列表和本地 404 详情页，确认错误原因完整、布局不溢出。

## 验收标准

- 404 上游仍不可用时，页面明确显示“上游主动重置连接”。
- 原始 `Errno 54` 错误仍可见。
- 已有成功倍率不会因一次网络失败消失。
- 倍率列不再被长错误文本撑坏或重复显示。
- 未调用任何真实主站新增、删除或完整编辑接口。
