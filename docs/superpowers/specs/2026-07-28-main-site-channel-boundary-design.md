# 主站渠道与本地监控节点边界收敛设计

## 背景

项目中同时存在两类被界面称为“渠道”的对象：

1. `sites` 表中的本地监控节点。它们由用户在本项目中手动添加，并分别配置 NewAPI 或 sub2api 的认证信息，由定时任务执行分组、倍率、模型和余额监控。
2. 用户自己 NewAPI 主站中的真实渠道。它们通过 `admin_sites` 保存的主站连接实时读取，不属于本项目的本地监控节点，也不应由本项目负责完整配置。

当前“主站监控”页面暴露了真实主站渠道的新增、删除、批量操作、状态切换、权重、分组、标签、密钥和渠道级上游登录配置。这超出了项目职责，也容易在测试本地节点 CRUD 时误删真实主站渠道。

## 目标

- 保持本地监控节点由用户手动添加、配置认证、检测、编辑和删除。
- 主站监控页面只负责展示主站已有渠道及其健康、分组和倍率信息。
- 主站真实渠道唯一允许的修改是 `priority`。
- 删除“主站监控”顶部的“删除主站”按钮，避免误导。
- 保留现有后端主站渠道接口，避免扩大本次改动范围，但前端不再暴露危险入口。
- 所有新增/删除流程测试只操作 `/api/sites`，不得操作真实主站渠道。

## 非目标

- 不删除或迁移现有 `admin_sites`、`channel_upstream_bindings`、`admin_channel_keys` 数据。
- 不删除现有 `/api/admin/sites/:id/channels` 后端写接口。
- 不在本项目中重建主站渠道配置后台。
- 不修改真实主站现有渠道数据，优先级编辑除外。
- 不自动把主站渠道导入或复制成 `sites` 记录。

## 数据与职责边界

### 本地监控节点

`sites` 是监控配置的唯一来源。新增节点继续使用 `POST /api/sites`，数据库通过 `AUTO_INCREMENT` 自动分配 ID。删除节点继续使用 `DELETE /api/sites/:id`，只删除本地记录及其级联历史，不请求主站渠道接口。

NewAPI 节点可进行公开分组监控；配置普通用户系统访问令牌和用户 ID 后，可读取专属分组、账户额度和用户 API 密钥。sub2api 节点继续要求账号密码或已导入的登录态。

### 主站渠道

`admin_sites` 只保存连接用户自己 NewAPI 主站所需的信息。主站渠道列表继续实时读取主站 `/api/channel`，不落入 `sites`。

主站渠道的 `base_url` 通过规范化地址匹配已启用的本地 `sites` 节点。匹配成功后，倍率查询复用该本地节点的认证信息。现有渠道级 binding 数据可以继续作为兼容回退，但界面不再提供新增或编辑渠道级认证配置的入口。

## 前端设计

### 本地“渠道监控”页面

保留以下能力：

- 手动添加 NewAPI/sub2api 监控节点。
- 编辑节点名称、Base URL、平台、认证、间隔和启用状态。
- 删除本地节点。
- 手动检测、定时监控、分组倍率、模型和余额查询。

调整说明文案，明确主站倍率匹配会按 Base URL 复用这里配置的登录态，不再提示去主站页面增删改渠道，也不再描述渠道级登录配置优先级。

### “主站监控”页面

保留：

- 主站选择、添加主站连接、编辑主站连接。
- 主站渠道列表、搜索、分组筛选、状态展示、权重展示、优先级展示。
- 分组与倍率展示、倍率刷新，以及列表响应中已有的渠道名称、类型、模型数量和掩码 key。
- 主站健康信息。

移除：

- “删除主站”按钮。
- “添加渠道”按钮。
- 单渠道“删除”按钮。
- 复选框和全部批量操作。
- 状态点击切换。
- 权重和优先级行内输入框。
- 主站渠道密钥、Base URL、模型、分组、权重、状态、标签、自动禁用、模型映射和渠道级登录信息的编辑控件。
- 主站渠道明文密钥的“显示/隐藏”入口；列表只展示主站列表接口返回的掩码，不因查看页面额外请求受保护的明文 key 接口。

“编辑”按钮改为打开仅包含 `priority` 数字输入框的弹窗。保存时只提交：

```json
{
  "priority": 10
}
```

弹窗不读取或提交其他渠道字段。主站渠道其他信息在列表中保持只读。

## 后端与 API

本次不改变现有 API 契约：

- 本地监控节点继续使用 `/api/sites`。
- 主站列表与渠道读取继续使用 `/api/admin/sites` 和 `/api/admin/sites/:id/channels`。
- 优先级编辑继续使用 `PUT /api/admin/sites/:id/channels/:channel_id`，请求体只包含 `priority`。
- 主站渠道新增、删除、批量操作和完整更新接口暂时保留，前端不再调用。

后端的主站渠道更新仍执行现有 read-merge-write，确保只提交 `priority` 时不会清空其他渠道字段。

## 错误处理

- 优先级保存失败时保留弹窗，并同时显示内联错误和 toast。
- 保存成功后关闭弹窗并重新读取主站渠道列表。
- 主站读取失败只影响主站展示，不影响本地 `sites` 的定时监控。
- 本地节点删除和主站渠道写接口在界面与测试命名中明确区分，避免再次调用错误端点。

## 测试与验收

### 自动验证

- 前端 TypeScript 检查和生产构建通过。
- 现有 NewAPI、sub2api、渠道 key 匹配和后端测试通过。
- 增加或调整测试，确认优先级弹窗只生成 `{ priority }` 请求。
- 确认主站页面不再渲染主站删除、渠道新增、渠道删除、批量修改、状态切换和权重编辑入口。
- 确认主站页面不会因用户查看渠道列表或点击渠道行而请求明文 key 详情接口。
- 确认本地节点删除仍调用 `/api/sites/:id`，没有调用 `/api/admin/sites/:id/channels/:channel_id`。

### 本地流程验证

使用测试数据或受控本地环境验证：

1. 删除一个本地 NewAPI 节点并重新添加，确认新 ID 自动分配、认证和手动检测正常。
2. 删除一个本地 sub2api 节点并重新添加，确认新 ID 自动分配、登录、分组、模型、余额和手动检测正常。
3. 打开主站监控页面，确认真实主站渠道正常显示，且没有新增、删除、批量修改入口。
4. 编辑一个主站渠道优先级，确认只修改 `priority`，其他主站渠道字段保持不变。

任何流程验证都不得删除或新建真实主站渠道。涉及现有用户数据时，优先使用非破坏性验证；确需删除重建本地节点时，只允许操作 `sites`，并提前记录用于重新添加的本地配置。

## 验收标准

- 用户可以清楚区分“本地手动监控节点”和“主站真实渠道”。
- 主站监控顶部不再出现“删除主站”按钮。
- 主站渠道没有新增、删除、批量修改、状态切换或权重编辑入口。
- 主站渠道编辑弹窗只有优先级字段。
- 本地 NewAPI/sub2api 节点仍可完整添加、编辑、删除和监控。
- 删除并重新添加本地节点时 ID 自动分配，且不会修改真实主站渠道。
