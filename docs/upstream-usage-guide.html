02

三类对象与数据流

绝大多数配置疑问，都来自把这三类对象混成一个。

本地数据库 · sites
渠道监控节点

代表你要长期盯盘的上游。由“添加渠道”创建，保存普通用户认证，参与定时检测。

  • 产生 snapshots 与 changes
  • 触发邮件 / 企业微信
  • 支持按需余额与模型健康
本地数据库 · admin_sites
主站连接

代表你自己的 NewAPI / sub2api 管理后台连接，保存管理员凭据，实时读取远端渠道。

  • 不进入定时快照
  • NewAPI UI 只改优先级
  • sub2api UI 可完整编辑和启停
远端系统
主站真实渠道

真实存在于 NewAPI / sub2api 主站。Upstream 只是通过管理接口读取或执行受限更新。

  • 不是本地 sites 记录
  • 删除主站连接不删除它
  • Base URL 可匹配本地监控登录态

定时监控链路

sites已启用节点
→
10 秒扫描找 next_check_at 到期项
→
协议采集NewAPI / sub2api
→
snapshots成功或失败快照
→
diff / changes与最近成功快照比较
→
通知邮件 + 企业微信
扫描周期是 10 秒，不等于每个站点每 10 秒采集；真实采集间隔由各站点的分钟配置决定，默认 3 分钟，最小 1 分钟。

NewAPI 主站渠道倍率匹配链路

主站真实渠道渠道 Key + Base URL
→
同 URL 的 sites复用普通用户登录态
→
/api/token/查用户自己的 Key
→
确定所属分组必要时精确读取 Key
→
用户分组接口读取实际倍率
这里使用上游普通用户权限，不应使用第三方上游的管理员令牌。主站渠道 Key 读取若受保护，首次可能需要合法 2FA；成功缓存后优先复用。

合理之处：监控数据与主站管理数据分离，避免管理员接口波动制造假变化，也避免每 3 分钟打一次远端管理后台。

历史样本不是实时状态：历史记录最近曾出现 8 个监控站点、1 个 NewAPI 主站连接、约 15,008 条快照和 188 条变化，但生成本文档时本机 8000 端口未运行，因此这些数字只用于容量估算。

历史会话反复验证出的边界

监控工具，不是 API 网关

它不负责请求转发、用户注册、计费、支付、密钥签发或流量调度；这些仍由 NewAPI / sub2api 承担。

同步登录态，不是突破验证

扩展复用你在 Chrome 中已经完成验证的会话，不会自动解 Turnstile / Cloudflare，也不能绕过 NewAPI 的 2FA 安全 proof。

倍率可见，不代表实时接口正常

页面可能从最近成功快照显示倍率；成功率、延迟、余额和主站列表通常需要实时请求，网络失败时会为空。

当前 UI 边界小于后端边界

NewAPI 主站页面只暴露优先级，但后端仍保留新增、批量修改和删除等写路由，需要用控制台密码和反向代理保护。

安装与启动

选择一种运行方式。生产模式必须先构建前端，Docker 镜像会自动完成构建。

前置：Python 3.11+、Node.js 20+、MySQL 8.0+。后端唯一第三方库是 PyMySQL。

适合：修改 React 页面并实时预览。后端 8000，Vite 5173，前端自动代理 /api。

准备数据库与后端
cd /path/to/upstream
cp .env.example .env

# 先编辑 .env，只在本地填写 DB_PASSWORD
mysql -u root -p -e "CREATE DATABASE IF NOT EXISTS upstream CHARACTER SET utf8mb4;"
python3 -m pip install -r requirements.txt
python3 app.py
另开终端启动前端
cd /path/to/upstream/apps/web
npm ci
npm run dev

访问 http://127.0.0.1:5173。

适合：在本机按生产结构运行，由 app.py 托管构建后的静态资源。

构建并运行
cd /path/to/upstream
python3 -m pip install -r requirements.txt
cd apps/web
npm ci
npm run build
cd ../..
python3 app.py

访问 http://127.0.0.1:8000。若缺少 apps/web/dist，后端会回退到旧 static 目录。

适合：服务器长期运行。Compose 自带 MySQL 8.4，并用命名卷 mysql-data 持久化。

一键启动
cd /path/to/upstream
cp .env.example .env

# 编辑 .env：至少设置 DB_PASSWORD 和 CONSOLE_PASSWORD
docker compose up -d --build
docker compose ps
curl http://127.0.0.1:8000/api/auth/status

宿主机 MySQL 已占用 3306 时，可在 .env 设置 DB_PORT=3307。应用容器始终通过 Docker 内网的 mysql:3306 连接，不受该映射影响。

启动后最小验证

只读健康检查
curl -i http://127.0.0.1:8000/api/auth/status
curl -i http://127.0.0.1:8000/api/overview
curl -i http://127.0.0.1:8000/api/sites

设置 CONSOLE_PASSWORD 后，后两个接口未登录返回 401 是正常现象；请从 Web 登录，不要把会话 Token 写进脚本或教程。

环境变量

.env 只负责运行环境；站点、主站和推送等业务配置由 Web UI 保存到 MySQL。

安全的 .env 示例
DB_HOST=127.0.0.1
DB_PORT=3306
DB_USER=root
DB_PASSWORD=<仅在本机填写强密码>
DB_NAME=upstream

HOST=127.0.0.1
PORT=8000
APP_TIMEZONE=Asia/Shanghai

CONSOLE_PASSWORD=<公网部署必须填写>
CONSOLE_SESSION_TTL=604800
变量默认值用途审查建议
DB_HOST / DB_PORT127.0.0.1 / 3306MySQL 地址Docker 内由 Compose 固定为 mysql:3306
DB_USER / DB_PASSWORDroot / 空数据库身份密码必填且只放 .env
DB_NAMEupstream业务数据库先创建 utf8mb4 数据库
DB_POOL_SIZE8每进程连接池，限制 1–328 个以内站点通常无需调整
DB_POOL_ACQUIRE_TIMEOUT5 秒连接池等待上限超时会快速失败而非无限阻塞
DB_CONNECT_TIMEOUT5 秒MySQL 建连超时跨机数据库可酌情提高
DB_READ_TIMEOUT / DB_WRITE_TIMEOUT15 秒MySQL 读写超时不要用极大值掩盖网络问题
UPSTREAM_HTTP_TIMEOUT15 秒上游 HTTP 单次超时，限制 1–120不改变主站 Key 请求 2 秒间隔
SLOW_REQUEST_THRESHOLD_MS500脱敏慢请求日志阈值设 0 可关闭
HOST / PORT127.0.0.1 / 8000监听地址与端口0.0.0.0 必须配控制台密码
APP_TIMEZONE / TZAsia/Shanghai展示时区，前者优先容器与应用保持一致
CONSOLE_PASSWORD空启用所有 API 的登录门禁公网或 Docker 映射必须设置
CONSOLE_SESSION_TTL604800 秒内存会话有效期，最小 300后端重启后需重新登录
SEED_DEMO0空库是否插入 Demo NewAPI生产保持 0，避免失败快照噪声

不要把业务密钥写进环境示例或 Git：站点密码、Token、主站渠道 Key、SMTP 密码和 Webhook 当前都存入 MySQL；数据库备份同样属于敏感文件。

06

渠道监控配置

入口：顶部“添加渠道”或“渠道监控”。这里创建的是 sites，也是定时监控、余额和变化记录的基础。

填写基本信息

名称用于识别；平台选 NewAPI 或 sub2api；Base URL 只填根地址，例如 https://api.example.com，不要附加 API 路径；检测间隔默认 3 分钟，最小 1 分钟。

选择认证方式

按下表选择。NewAPI 可关闭认证增强只监控公开分组；sub2api 必须有可用登录态。

测试或同步

手动 Token 模式使用“测试连接 / 测试认证”；浏览器模式先检测扩展，再保存并同步真实会话。

保存并立即检测

保存后在渠道表点击“检测”。确认状态、公开分组、认证分组、上次检测和下次检测符合预期。

平台 / 模式需要填写读取能力适用情况
NewAPI 公开模式Base URL/api/user/groups只看公开默认分组
NewAPI 浏览器同步同一 Chrome 已登录普通用户隐藏/专属分组、余额、用户 Key 匹配推荐，减少手工复制 Token
NewAPI 手动令牌普通用户系统访问令牌 + NewAPI 用户 ID/api/user/self、用户分组不使用扩展时
sub2api 浏览器同步Chrome 中的 auth_token + refresh_token；账号密码可选兜底实际分组倍率、模型、余额、订阅推荐，适合已完成人机验证
sub2api 账号密码普通用户邮箱 + 密码登录后完整监控能力站点没有 Turnstile 或登录限制
sub2api 手动登录态auth_token；refresh_token 建议填写；到期时间可选与浏览器登录态相同无法安装扩展时

NewAPI 监控节点只填普通用户令牌。系统访问令牌继承所属账号角色；如果填第三方上游的管理员令牌，一旦泄露会扩大到渠道、用户和日志权限。

编辑与删除规则

  • 密码或 Token 已保存时，编辑表单留空表示保持不变。
  • 切换平台或认证模式会清理不兼容凭据，避免 NewAPI 与 sub2api 串线。
  • 删除监控节点会通过外键级联删除该节点的快照、变化和登录态同步请求，不可撤销。
  • 浏览器同步失败不会回滚已保存节点，可选择打开上游登录页、重新同步或稍后处理。
07

主站监控配置

入口：“主站监控”。这里保存 admin_sites，实时读取你自己的中转站后台，不参与定时 diff。

NewAPI 主站
管理员令牌 + 用户 ID

用于读取 /api/channel 与分组。另可配置管理员网页登录账号/密码或同步现代浏览器会话，受保护 Key 读取需要合法 2FA proof。

  • 页面列出真实渠道与分组
  • 按 Base URL 匹配本地 sites 登录态
  • 当前 UI 仅刷新倍率和调整 priority
sub2api 主站
管理员邮箱 + 密码

登录后只读取管理员渠道与分组接口，不读取号池。UI 可编辑现有渠道的白名单字段、模型定价、映射、高级计费和启停状态。

  • 不支持管理员 API Key
  • 不开主站浏览器同步
  • 不在 Upstream 新建或删除真实渠道

能力边界

能力NewAPI 主站sub2api 主站是否进入快照 / 通知
实时渠道列表与分组支持支持否
渠道 Key 对应上游倍率支持，复用 sites 普通用户登录态不走此链路否
优先级调整当前 UI 支持包含在完整编辑能力内否
完整编辑与启停当前 UI 隐藏按 capabilities 支持否
新增 / 删除真实渠道当前 UI 不提供禁止否
号池读取不适用明确不访问否

UI 与后端能力不完全相同：当前 NewAPI 页面不提供新增、删除、批量操作或完整编辑，但 app.py 仍保留相关写接口。只隐藏按钮不是安全边界，必须启用 CONSOLE_PASSWORD 并限制网络访问。

正确配置顺序

  1. 先在“渠道监控”添加上游 sites，配置普通用户登录态并测试。
  2. 再在“主站监控”添加自己的主站连接，使用最小权限的管理员凭据。
  3. 确保主站真实渠道的 Base URL 与本地 sites 的 Base URL 归一化后相同。
  4. NewAPI 首次读取受保护 Key 时按页面提示完成 2FA；成功后本地缓存，后续优先复用。
  5. 刷新渠道倍率，检查“精确匹配 / 部分匹配 / 待验证 / 刷新失败”等状态，不要把最近成功数据误认为当前实时值。
08

浏览器登录态同步

扩展版本 0.1.2。它把同一 Chrome 中已经登录的会话直接提交到本机后端，React 页面不会拿到 Token。

加载本地扩展

打开 chrome://extensions，启用开发者模式，点击“加载已解压的扩展程序”，选择 /path/to/upstream/extensions/upstream-session-bridge。

从回环地址打开控制台

必须用 http://127.0.0.1:8000 或 http://localhost:8000。扩展 content script 不匹配局域网 IP、自定义域名或 IPv6 [::1]。

提前打开并登录上游

同一个 Chrome 中保留目标上游标签页。标签页的 scheme、host、port 必须与 Base URL Origin 完全一致；扩展只寻找已打开标签页，不会自动创建。

检测扩展并保存同步

“检测同步扩展”只确认桥接可用；真正读取登录态发生在保存或“重新同步”时。页面等待结果最多约 25 秒。

对象读取来源要求不会做什么
NewAPI 普通监控站点现代会话、new_api_refresh，并兼容部分旧 Local Storage同 Origin 已登录普通用户不会把令牌返回 React 页面
NewAPI 主站现代管理员浏览器会话仍需管理员系统令牌、用户 ID；Key 读取可能仍需 2FA不会用普通用户旧 Local Storage 替代管理员会话
sub2api 监控站点Local Storage 的 auth_token、refresh_token、token_expires_ataccess 与 refresh Token 同时存在不读密码或 Cookie

权限范围较宽：Manifest 声明 tabs、scripting、storage、cookies，以及所有 HTTP/HTTPS 站点访问权限。只从可信的本地源码加载，修改后重新审查。

Cookie 权限实际用于 NewAPI；sub2api 只读页面 Local Storage。凭据不写扩展存储，不输出日志。

不能绕过人机验证：扩展只能复用你已经在浏览器里合法完成的人机验证和登录会话。若会话缺失、过期、Origin 不一致或上游 API 仍要求验证，必须回到上游页面手动完成。

09

检测、快照与变化

只有 sites 走这条链路。主站连接和远端真实渠道不会进入定时采集。

每次检测做什么

采集公开或用户实际分组

NewAPI 先取公开分组，认证增强时再取用户分组；sub2api 通过当前认证模式读取可用分组与用户专属倍率。

写入快照

成功与失败都会写入 snapshots。成功快照保存规范化分组、原始响应摘要和 hash。

与最近成功快照比较

首个成功快照建立基线，不发送变化；后续比较分组、倍率、描述、状态、专属、订阅、RPM、平台和模型名单。

记录变化并通知

每条变化写入 changes，然后聚合成邮件和企业微信消息。认证增强失败会使站点为 warning，但公开采集结果仍可保留。

变化类型含义严重度逻辑
group_added新增分组，消息含倍率（若有）信息
group_removed分组被删除严重
ratio_changed倍率变化并计算百分比上涨为警告，下降为信息
desc_changed分组描述变化信息
status_changed 等状态、专属、订阅、RPM、平台字段变化信息
model_added_to_group某分组上架模型信息
model_removed_from_group某分组下架模型警告

模型上下架只在新旧快照都包含模型名单时比较。任一侧缺失就跳过，避免把缓存未加载误报成整组模型下架。

状态如何变化

  • 采集成功且认证增强无错误：ok，连续失败归零。
  • 公开采集成功但认证增强失败：warning。
  • 调度异常连续不足 3 次：warning；达到 3 次：failed。
  • 页面每 15 秒刷新站点、最近 50 条变化和通知设置；这不是重新检测上游。
  • “立即检测”会直接运行单站检测。仅 sub2api + browser 在返回需要同步时会自动同步并重试一次。
10

余额与模型健康

这两类数据多数是按需实时查询，不应与数据库里的最后快照混为一谈。

NewAPI
/api/user/self

读取剩余额度、已用额度、请求次数和用户分组。按默认 500000 额度 = 1 美元折算展示。

sub2api
/api/v1/auth/me

读取余额、冻结余额、累计充值、RPM 上限，以及订阅的日 / 周 / 月用量和到期时间。

余额页面的真实行为

  • 只包含“渠道监控”里的 sites，不包含 admin_sites。
  • 进入页面不会自动查询，必须点击单站“查询”或“一键查询”。
  • 一键查询逐站串行，不使用 Promise.all 并发洪峰；单站失败后继续下一站。
  • 只把成功结果计入合计，失败行保留各自错误。

模型健康

平台主要接口展示内容失败时
NewAPI/api/pricing、uptime / perf-metrics模型目录、成功率、延迟、时间窗口汇总可能仍显示上次倍率，但实时性能为空
sub2api/api/v1/channels/available、/api/v1/channel-monitors分组模型、渠道监控状态分组名为空时会做规范化与倍率消歧

看到“倍率正常、成功率和延迟为空”时，先检查实时接口和网络。倍率可能来自 MySQL 最近成功快照，并不证明当前 TCP、代理或上游 API 正常。

消息推送

入口：“消息推送”。当前只维护邮件与企业微信，不复活 QQ 推送。

企业微信
群机器人 Webhook

填写完整 Webhook，启用开关，测试发送。无需服务器回调。

  • Webhook 保存到 MySQL
  • 测试结果记录 notification_logs
  • 错误显示最近一次失败原因
邮件
SMTP + SSL / STARTTLS

填写主机、端口、账号、授权码或密码、发件人和收件人。多个收件人用逗号分隔。

  • SSL 默认端口 465
  • 非 SSL 分支使用 STARTTLS
  • 编辑时密码留空保持不变

推荐配置顺序

  1. 先关闭两个启用开关，填写完整字段。
  2. 启用目标通道，点击页面底部“保存配置”；该按钮同时保存邮件与企业微信两组表单。
  3. 分别点击“测试企业微信”和“测试邮件”，确认状态文案与实际接收。
  4. 手动触发一个可控变化或等待下一次真实 diff，确认自动通知。

测试接口会携带当前表单值，后端在发送前更新设置；操作上仍建议显式点击“保存配置”，以便页面状态和审查流程清晰。

SMTP 密码和企业微信 Webhook 当前以可用明文形式保存在 MySQL。不要把数据库导出上传到公开仓库、网盘公开链接或聊天记录。

备份与迁移

运行期数据以 MySQL 为准。data/app.db 只是旧 SQLite 迁移源，不是当前主库。

MySQL 备份

密码由终端交互输入，不写命令行
cd /path/to/upstream
mkdir -p backups
mysqldump -h 127.0.0.1 -P 3306 -u root -p \
  --single-transaction --routines --triggers upstream \
  > backups/upstream-$(date +%F).sql

恢复前先建空库

恢复会修改目标数据库，请先确认文件与目标
mysql -h 127.0.0.1 -P 3306 -u root -p \
  -e "CREATE DATABASE IF NOT EXISTS upstream CHARACTER SET utf8mb4;"
mysql -h 127.0.0.1 -P 3306 -u root -p upstream \
  < backups/upstream-2026-08-01.sql

旧 SQLite 迁移到 MySQL

默认幂等 upsert，不清空目标
python3 scripts/migrate_sqlite_to_mysql.py \
  --sqlite data/app.db
Docker 内执行
docker compose run --rm upstream \
  python scripts/migrate_sqlite_to_mysql.py \
  --sqlite data/app.db

默认不要使用 --truncate。它会在导入前删除 MySQL 的 sites、snapshots、changes、notification_settings 和 notification_logs 五张业务表中的数据。

迁移脚本只搬旧 SQLite 中这五张表，不包含后来新增的 admin_sites、渠道绑定、Key 缓存和浏览器同步请求。

Docker 数据注意事项

  • MySQL 正式数据在命名卷 mysql-data，升级容器时不要删除该卷。
  • ./data:/app/data 只为旧 SQLite 迁移提供挂载；纯 MySQL 生产环境可移除，减少旧明文库进入容器。
  • 备份完成后校验文件大小，并在隔离数据库做一次恢复演练。

安全与合理性审查

以下是基于当前代码和历史运行样本的审查结论，可直接逐项决定是否接受或整改。

审查项当前判断理由建议
sites 与 admin_sites 分离合理定时监控和实时管理接口职责不同继续保持，不合表
双协议适配合理认证、分组、Key、模型和余额接口明确分支新增协议能力时补隔离测试
stdlib 后端 + PyMySQL适合当前规模依赖少，8 个左右站点足够站点数大幅增长再评估队列与异步架构
控制台密码默认关闭公网不合理未启用时所有 API 可直接访问Docker / 0.0.0.0 必须设置密码、HTTPS 和 IP 白名单
敏感字段存 MySQL有风险站点密码、Token、Key、SMTP 密码和 Webhook 需可直接使用限制 DB 权限、加密磁盘、严格备份权限；后续可做应用层加密
NewAPI 后端隐藏写接口边界不完整UI 隐藏但新增、批量、删除、完整更新路由仍存在若确定不用，应在后端加只读开关或移除路由
快照保留策略缺失代码未发现自动清理 snapshots先备份，再设计按月归档或保留天数
删除监控节点需要谨慎外键级联删除快照和变化删除前导出该站历史，UI 保持二次确认
浏览器扩展权限功能需要但范围宽声明全部 HTTP/HTTPS 站点与 Cookie 权限只加载可信本地源码，定期审查 Manifest
主站不进通知合理避免实时管理接口波动制造变化噪声若以后需要，单独设计主站健康告警，不混用快照

容量估算

8 站点 × 3 分钟
约 3,840 快照 / 天

无论是否发生变化，每次检测都会产生快照。

按历史样本折算
约 1.4M 快照 / 年

历史约 15,008 条快照曾占约 47 MB，粗估约 3 KB / 条。

未设清理策略
约 4–5 GB / 年

仅作容量规划，实际取决于原始 JSON、模型名单和失败信息长度。

最低上线门槛：CONSOLE_PASSWORD 非空、HTTPS 反代、IP 白名单或 VPN、MySQL 不暴露公网、备份文件 600 权限、扩展只在受控浏览器加载。

为什么“只隐藏危险按钮”不够安全？
浏览器 UI 不是权限边界。拥有网络访问的人可以绕过页面直接调用 API；当前后端只由控制台 Bearer 会话保护，没有针对“只读用户”和“管理员操作”的细粒度 RBAC。因此公网部署必须先保护整个控制台。
是否应该马上给数据库敏感字段加密？
方向合理，但要先设计主密钥来源、轮换、备份恢复和旧数据迁移。只把固定密钥写进源码或同一份 .env，保护收益有限。当前更优先的是网络隔离、最小权限、磁盘加密和备份管理。

故障排查

先判断是“本地服务、数据库、网络、认证、协议还是实时接口”，不要先删除站点或重新填写所有凭据。

现象优先判断处理顺序
127.0.0.1:8000 Connection refused后端没启动或端口不同检查进程 / Compose → 查看日志 → 启动 app.py
所有不同域名同时 Connection refused长期进程缓存了已失效的 macOS 系统代理检查当前代理 → 重启 app.py → 再检测；不要先改 Token
单站被重置连接 / 超时上游网络、防护或瞬态故障浏览器直接访问 → curl 根地址 → 稍后重试 → 保留最近成功值
扩展不可用控制台不是 localhost / 127.0.0.1，或页面未刷新检查扩展 0.1.2 → 刷新控制台 → 检测同步扩展
找不到上游标签页未提前打开，或 Origin 不一致打开 Base URL 根地址并登录 → 保持标签页 → 重试
人机验证失败扩展没有可复用的已验证会话在上游页面手动完成验证 → 确认 Token 存在 → 重新同步
NewAPI 401令牌与 NewAPI 用户 ID 不匹配或已过期用普通用户重新生成系统令牌 → 填本人 ID → 测试认证
NewAPI 403 SECURITY_PROOF_REQUIRED主站渠道 Key 受 2FA 保护且本地无缓存编辑主站 → 输入当前 2FA → 验证 Key 读取 → 刷新倍率
倍率有值但成功率 / 延迟为空倍率来自历史快照，实时接口失败查看原始错误 → 检查代理 / perf-metrics → 不要当成倍率采集正常证明
主站渠道待配置登录态没有同 Base URL 的本地 sites 或认证不完整先建监控节点 → 配普通用户登录态 → 确保 URL 归一化一致
模型显示 0/0模型缓存未取到、分组名缺失或接口版本不兼容打开倍率 / 模型详情触发预热 → 检查 channels/monitors 响应 → 看映射错误
一键余额部分失败上游单站认证或网络失败当前已串行；逐站单查 → 对照错误 → 不要全局重试登录
修改代码后页面仍是旧版后端托管旧 dist 或旧进程npm run build → 重启 app.py / 重建容器 → 强制刷新
