# 第 1 章 开始之前：先弄懂三个概念

## 1.1 这个系统是干什么的

Upstream 是一个「上游 AI 中转分组倍率监控 + 主站渠道管理」控制台，核心能力五件：

1. **盯上游**：定时采集 NewAPI / sub2api 上游站点的分组、倍率、描述、模型上下架，发现变化自动记录并推送（邮件 + 企业微信）。
2. **管主站**：接入你自己的 NewAPI / sub2api 中转站后台，实时读取渠道和分组，做优先级调整、启停、配置编辑。
3. **对账同步**：把主站里的渠道批量同步成本地监控站点（按 Base URL 对账，上游消失的渠道自动停用或删除）。
4. **key 匹配**：读出主站渠道的真实 key，去上游匹配当前倍率（含 2FA 安全验证）。
5. **查余额**：按渠道的登录态查询账户余额 / 额度 / 订阅用量。

## 1.2 两种「站点」——全系统最重要的区分

系统里有两个**互相独立、不共用令牌、不互相关联**的站点概念。看不懂这个，后面每页都会懵：

| | 渠道（监控站点） | 主站（管理站点） |
|---|---|---|
| 是什么 | **别人的或自己的上游站点**，你只读盯梢 | **你自己的中转站后台**，你有管理权 |
| 数据表 | `sites` | `admin_sites` |
| 在哪些页面出现 | 总览 / 渠道监控 / 渠道详情 / 变化记录 / 余额 | 主站监控 / 总览底部「主站健康」 |
| 用什么凭证 | 普通用户令牌 / 浏览器登录态 / 账号密码（可选） | NewAPI：**管理员**系统令牌+用户 ID（读 key 另配网页账号密码）；sub2api：管理员邮箱+密码 |
| 产生什么数据 | 定时快照、变化记录、推送 | 不产生快照、不推送，只实时读取 |
| 删除影响 | 删除本控制台的监控记录 | 只从本控制台移除，不影响上游后台真实渠道 |

> ⚠️ 渠道监控站点是**别人家的上游**时，切记填**普通用户**令牌，千万别填管理员令牌——令牌继承账号角色，泄露会连带暴露对方的渠道/用户/日志管理权限。

## 1.3 浏览器登录态同步（Chrome 扩展）

很多上游有 Cloudflare 人机验证，程序化登录经常被拦。解决办法是装浏览器扩展 `upstream-session-bridge`（`extensions/` 目录）：

- 它把你在 Chrome 里**已登录**的上游站点会话（cookie 等）同步给后端，后端拿这个登录态去采集数据。
- **扩展只注入 localhost / 127.0.0.1 页面**：必须用 `http://localhost:5173`（开发）或 `http://localhost:8000`（生产托管）访问控制台，用局域网 IP 或域名访问时同步必然失败。
- 登录态有 9 种终态（见附录 A），失效后可点「同步」按钮重新拉取；NewAPI 渠道还可开启「兜底系统访问令牌」自动续命（见第 6 章）。

## 1.4 后台业务总流程（四条链路）

**链路一：监控检测（每渠道独立定时）**
调度器按渠道的 `监控间隔` 触发检测 → 按认证方式采集分组（公开接口，或用登录态读该账号实际可见分组）→ 写入一份快照 → 与上次成功快照 diff → 有差异就写「变化记录」（倍率变化 / 分组增删 / 描述变化 / 模型上下架等 10 类）→ 变化经配置好的邮件 / 企业微信通道推送 → 前端每 15 秒轮询刷新展示。连续失败会累计，状态随之变「警告 / 异常」。

**链路二：主站同步（手动触发）**
读主站全部渠道 + 分组 → 先落快照、再按上游 Base URL 与本地监控渠道对账 → 上游新增的导入为监控渠道、消失的按主站配置「停用」或「删除」→ 写入「发现来源」关联（渠道详情页可见）。同时按主站的「快照保留天数」定期清理过期快照与变化记录。

**链路三：key 匹配（主站渠道 ↔ 上游倍率）**
对 NewAPI 主站渠道：先用主站网页账号建立会话（必要时过 2FA）换取短期「渠道 key 读取」授权 → 读取该渠道的真实 key → 拿 key 去上游查询它实际绑定并可用的分组倍率 → 结果存为渠道的「上游绑定」。失败时不丢旧数据，界面显示上次成功倍率并标注原因。

**链路四：余额查询（点按钮才查）**
余额页 / 详情页点击查询时，后端用该渠道的登录态实时请求上游（NewAPI `/api/user/self`，sub2api `/api/v1/auth/me`），返回余额、用量、订阅信息。**不会**定时自动查，避免频繁登录触发上游风控。

# 第 2 章 第一次使用：推荐配置顺序

1. **装扩展**：Chrome 加载 `extensions/upstream-session-bridge`（0.1.8+），并在你要监控的上游站点上登录好账号。
2. **用 localhost 打开控制台**并登录（第 3 章）。
3. **添加主站**：主站监控 → 「添加主站」，填管理员凭证，「测试连接」通过后保存（第 5 章）。
4. **同步主站**：主站监控 → 「同步主站」，选范围把主站渠道批量导入为监控渠道（第 5 章）。也可以在渠道监控手动添加单个上游（第 6 章）。
5. **补登录态**：渠道监控 → 「同步 sub2api 登录态」/「同步 NewAPI 登录态」一键把浏览器登录态灌给各渠道（第 6 章）。
6. **配推送**：消息推送页配企业微信 / SMTP，各点一次「测试」确认能收到（第 10 章）。
7. **回总览验收**：看 KPI 是否正常、跑一轮「检测」、等第一封变化推送。

| 控件 | 说明 |
|---|---|

# 第 4 章 总览

## 4.1 这页是干什么的

全局仪表盘：渠道健康一屏看完（KPI + 渠道概览表）、最近变化滚动、底部汇总所有主站的渠道健康。数据来自共享轮询（15 秒自动刷新），主站健康面板例外——只在进入页面时拉一次，避免频繁打上游管理接口。

## 4.2 KPI 卡片怎么读

| 卡片 | 含义 |
|---|---|
| 监控渠道 | 渠道总数 |
| 启用中 | `启用监控` 开着的渠道数 |
| 正常 | 启用中且最近一次检测 `status=ok` 的渠道数 |
| 异常 | 启用中且状态为「警告 / 异常」的渠道数；>0 时红色高亮 |
| 最近变化 | 变化记录总数（系统最多保留最近 500 条展示） |

## 4.3 「渠道概览」面板

- 右上角「平台分类」下拉：全部平台 / NewAPI / sub2api，纯前端过滤。
- 表格为精简模式（无操作列）：渠道、状态、登陆态、上次检测。每列徽标含义见第 6 章 6.2 的表格说明与附录 A。
- 点击渠道行本身不跳转；完整操作请在「渠道监控」页进行。

## 4.4 「最近变化」面板

最近 50 条变化（完整列表在「变化记录」页），列含义见第 8 章。

## 4.5 「主站健康」面板（页面底部）

点击「刷新」按钮才会重新拉取：`GET /api/admin/sites` 拿主站列表，再对每个主站并发调 `GET /api/admin/sites/{id}/channels` 读渠道。后端按平台分发：NewAPI 打主站 `/api/channel`，sub2api 打 `/api/v1/admin/channels`。

| 控件 / 区域 | 说明 |
|---|---|
| 4 个 KPI | 渠道总数 / 运行中（active 或 status=1）/ 已停用（disabled 或 status=2）/ 异常（其余）。只统计本面板成功读到的渠道 |
| 「N 个 NewAPI 渠道被自动停用，请排查」红条 | 只列 NewAPI 原始状态 `3`（被上游自动停用）的渠道；每个渠道名后有「重新启用」链接，点击 → `PUT /api/admin/sites/{主站id}/channels/{渠道id}` `{status: 1}`，成功后自动重读本面板。注意：sub2api 的 `disabled` 是正常停用，不算自动故障，不在这里出现 |
| 黄色警告条 | 某主站渠道读取失败时列出失败原因（如登录态失效、网络错误） |
| 「刷新」按钮 | 见上，重新执行一次完整读取；成功 / 失败都会弹 toast |
| 「去管理 →」链接 | 跳转「主站监控」页 |

# 第 5 章 主站监控

这是功能最重的一页：管理你自己的 NewAPI / sub2api 主站连接，读取实时渠道与分组，并提供按平台能力区分的管理操作。

## 5.1 这页是干什么的

- NewAPI 主站：读渠道列表、分组倍率，支持**编辑优先级**、**刷新倍率**、**刷新 key**（这些动作需要 2FA 安全验证时页面会就地拦截）。
- sub2api 主站：读渠道与分组配置，支持**完整编辑**和**启用 / 停用**，**不允许**新建 / 删除渠道，也**不提供** key、匹配、批量、测试类操作（后端对这些 NewAPI 专属路由直接返回 405）。
- 页面按后端返回的「能力字段」渲染按钮，不会向 sub2api 发它不支持的请求。

## 5.2 页面结构

- 左侧「分组视角」侧栏：分组卡片列表，可点击筛选右侧渠道表，可拖拽排序（顺序存浏览器本地，只影响本机显示）。
- 右侧渠道主区域：NewAPI 显示表格，sub2api 显示表格。
- 选中某个 NewAPI 渠道后，页面底部出现「倍率详情」面板。
- 顶部错误横幅（红色）显示操作失败原因，可关闭；黄色条提示「刷新失败，当前显示上次成功数据」。

## 5.3 主站选择与工具栏按钮

| 按钮 | 点击后发生什么（前端 → 后端） |
|---|---|
| 主站下拉框 | 切换当前操作的主站；选项文案含 `平台 · 名称 · Base URL`，未配置凭证的主站会标注「未配置令牌」/「未配置管理员密码」。切换后自动加载该主站的渠道、分组、上游绑定：`GET /admin/sites/{id}/channels` + `GET /admin/sites/{id}/groups`（+ NewAPI 还有 `GET /admin/sites/{id}/channel-mappings` 读上游绑定汇总）。某主站首次进入时自动为每个渠道跑一次倍率匹配刷新（每个会话只自动刷一次） |
| 「同步主站」 | 见 5.4，两步：先弹范围选择，再执行同步 |
| 「刷新倍率」 | 见 5.5，一键并发刷新当前主站全部渠道的上游倍率（复用已保存的 key） |
| key 刷新状态徽章 | 展示后台全量 key 刷新批次进度（进行中 / 已完成 N/M · 失败 X / 已暂停需重新验证 2FA / 失败+原因），每 10 秒自动轮询 `GET /api/admin/sites` 更新 |
| 倍率刷新状态徽章 | 同上，展示全量倍率刷新批次进度 |
| 「编辑主站」 | 打开「编辑主站」弹窗（见 5.7），回填当前主站配置 |
| 「添加主站」 | 打开「添加主站」弹窗（空表单） |

## 5.4 「同步主站」——主站渠道对账导入（核心流程）

**第一步：选范围。** 点「同步主站」后：

- sub2api 主站：没有范围弹窗，直接按「全部」执行（sub2api 渠道没有上游地址可发现）。
- NewAPI 主站：弹出「同步主站」弹窗。前端先调 `GET /api/admin/sites/{id}/channel-candidates` 拿可同步候选（按平台识别筛过，只留 NewAPI / sub2api），弹窗内三个选项：
  1. **全部渠道**（默认，跟随主站配置 `同步范围`）：导入全部渠道指向的上游站点；
  2. **仅识别 NewAPI / sub2api**：只导入平台识别命中的渠道，并且把本地已导入但平台不符的站点**直接删除**；
  3. **勾选渠道**：列表勾选具体候选（支持「全选 / 清空」），只导入勾选渠道的站点，未勾选的保持不动。
  点「取消」关闭；点「开始同步」进入第二步。

**第二步：执行同步。** 前端调 `POST /api/sites/sync`（参数：主站 id、scope、勾选的 channelIds）。后端逻辑：

1. 用主站凭证实时读取主站渠道 + 分组，先把整份快照落库（同步中途挂了上游现状已保住；任一渠道 base_url 非法则整次同步拒绝执行，防止在上游数据不完整时做删除类清理）；
2. 渠道按上游 Base URL 聚合成候选（同注册域名的多个渠道合并为一个上游站点）；
3. 按选定范围过滤（**平台识别只在「仅识别 / 勾选」范围下运行**，「全部渠道」不做识别）；
4. 按上游 Base URL 与本地监控渠道对账：**上游有、本地没有 → 自动创建监控渠道**；**上游消失 → 按主站配置的「消失渠道处理」停用或删除**（判定依据是站点的「来源关联」是否全部失效；auto_disabled 的站点重新拿到活关联会自动恢复启用）；「仅识别」模式下平台不符的本地站点直接删除；不在同步范围内的渠道站点跳过不动；
5. 更新「发现来源」关联表（渠道详情页的「发现来源」面板数据源）。

完成后弹 toast 汇总：`新增 X · 恢复 X · 停用 X · 删除 X · 平台冲突 X · 跳过 X 个未识别渠道`；读取失败时提示「N 个主站读取失败」。**注意：同步本身不刷新渠道 key**（key 刷新由「自动更新渠道 key」和「刷新 key / 刷新倍率」触发，见 5.5）。渠道监控页还有一个无范围弹窗的「同步主站」按钮，一次性同步**全部**主站（多主站并发），逻辑相同。

> ⚠️ 「仅识别」模式会**删除**平台不符的本地站点及其全部快照与变化记录，不可恢复；「消失渠道处理=删除」同理。不确定时选「全部渠道」+「停用」。

## 5.5 「刷新倍率」与 2FA 安全验证

点「刷新倍率」时，前端先做安全检查：

- 当前 NewAPI 主站**没有有效的安全凭证（proof）**，或上一次全量批次处于「已暂停」状态 → 先弹出「重新验证主站 2FA」弹窗（见 5.6），验证通过后自动继续；
- 凭证有效 → 直接调 `POST /api/admin/sites/{id}/channels/ratios/refresh`，后端启动一个**后台批次**：逐个渠道用已保存的真实 key 去上游匹配当前倍率（并发受控），进度写回主站记录；
- 前端出现「倍率刷新中 N/M」徽章并每 10 秒轮询进度，完成后 toast 汇报「成功 N/M，失败 X」并自动重载列表。

单渠道行的「刷新倍率」按钮同理：没有 proof 时先弹 2FA，验证通过后跑单渠道匹配 `POST /admin/sites/{id}/channels/{cid}/match`。

匹配结果怎么读（表格「当前 key 上游倍率」列）：

- **绿色 / 警示色倍率徽章**（如 `×1.5`）：匹配成功；鼠标悬停弹出浮层，展示同源监控站点的全量分组目录并高亮当前 key 命中的分组；
- **虚线徽章**：站点登录态失效，显示的是**上次成功匹配**的旧倍率（数据仍可用但非实时）；
- **状态徽章**：`站点未登录`（先去渠道监控同步登录态）/ `上游分组不存在` / `上游 key 未匹配` / `需要安全验证` / `缺少渠道 key` / `上游未匹配`。徽章悬停可见原始错误。

# 第 6 章 渠道监控

## 6.1 这页是干什么的

管理全部**监控渠道**（sites）：列表、筛选、逐渠道手动检测、登录态同步、批量从主站同步。这里是监控链路的入口——渠道配置好了，调度器就会按间隔自动盯梢。

| 「同步」(铅笔) | sub2api 且非浏览器模式 | 直接打开「编辑渠道」弹窗去更新令牌 / 账号密码 |

# 第 12 章 附录 B：常见问题

**Q1：「扩展未连接」怎么办？**
确认三件事：① 地址栏是 `http://localhost:…`（127.0.0.1 也行），不是局域网 IP 或域名；② 扩展已启用且是最新版——到 `chrome://extensions` 点刷新，然后 **Cmd+Shift+R 强刷控制台页面**；③ 弹窗里点「检测同步扩展」复查。

**Q2：渠道一直「站点未登录 / 登录态已失效」？**
去渠道监控页点该渠道行内「同步」，按弹窗引导在上游站点登录后点「我已登录完成」。NewAPI 渠道开了兜底令牌的话，检测会自动降级用令牌读，不阻断监控。

**Q3：主站渠道显示「需要安全验证」？**
主站开了 2FA，读取 key 的授权过期了。点行内「刷新倍率 / 刷新 key」或顶部「刷新倍率」，在弹窗输入当前 6 位验证码即可，验证通过会自动继续刚才的动作。

**Q4：「上游 key 未匹配 / key 已不在上游」？**
主站里这个渠道的真实 key 变了或渠道已失效。先点「刷新 key」重读；仍失败就去主站后台确认渠道本身是否可用。

**Q5：「防护拦截」和「网络异常」要紧吗？**
这两种与登录态无关：一个是上游 WAF 拦了你的机器，一个是网络不通。换出口（VPN / 代理）等下一轮检测自动恢复；如果长期如此，考虑拉长监控间隔。

**Q6：同步主站会不会误删我的监控渠道？**
对账只动「从主站同步导入」的站点：上游消失的渠道按主站配置「停用 / 删除」。把「消失渠道处理」设为「停用」最安全；「仅识别 NewAPI / sub2api」范围会额外删除平台不符的站点，不确定就别选。手动添加的渠道不受对账影响。

**Q7：为什么余额要点按钮才查？**
sub2api 密码模式每次查询都要真实登录一次上游，NewAPI 令牌模式也会消耗上游请求配额。系统刻意做成手动按需查询，避免风控。

**Q8：监控渠道该填管理员令牌吗？**
**绝不**。监控别人站点用普通用户令牌（继承的角色小，泄露损失小）；管理员令牌只填在「主站监控」里你自己的站点上。

**Q9：sub2api 主站能新建 / 删除渠道吗？**
不能。sub2api 主站只支持编辑既有渠道和启停切换；新建 / 删除 / key / 批量 / 测试是 NewAPI 专属能力，后端会直接拒绝。

**Q10：快照和变化记录会无限增长吗？**
不会。每个主站可配置「快照保留」（7～365 天或永久），后台定期清理过期快照与变化记录。

**Q11：页面数据多久自动刷新？**
渠道列表、变化记录等 15 秒轮询一次，也可随时点顶栏「刷新」立即拉取。「主站健康」面板例外（只在进入页面 / 手动点击时读取），主站渠道表按进入页面时读取。

**Q12：删除渠道 / 主站影响什么？**
删除监控渠道：本渠道全部快照与变化记录一并删除，不可恢复。删除主站：只从控制台移除主站连接，不影响上游后台的真实渠道；其名下同步导入的监控站点与关联关系同时清理。
